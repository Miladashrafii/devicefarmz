# DeviceFarmz

**یک قفسه گوشی را به آزمایشگاه تست مشترک تبدیل کنید.**
گوشی‌های واقعی را از مرورگر کنترل کنید، به CI و Appium بسپارید، و بعد از هر استفاده خودکار تمیز تحویل بگیرید.

[English](README.md)

![Fleet overview](docs/screenshots/devices.png)

</div>

## چرا؟

گوشی‌ها توی کشو بمانند مقیاس‌پذیر نیست: همه می‌پرسند «پیکسل دست کیه؟»، تست‌ها داده‌ی شخصی روی گوشی جا می‌گذارند و CI نمی‌تواند دستگاه قرض بگیرد. DeviceFarmz دستگاه‌ها را به یک ماشین وصل می‌کند و به همه — آدم‌ها و پایپ‌لاین‌ها — راهی منصفانه، تمیز و قابل‌پیگیری برای استفاده از آن‌ها می‌دهد.

## امکانات

- 🖥️ **کنترل از مرورگر:** صفحه‌ی H.264 با تأخیر کم، لمس، تایپ، Back/Home/Recents/Power، شل، logcat، مرورگر فایل، نصب APK، باز کردن URL، فوروارد پورت
- 🤖 **مناسب اتوماسیون:** رزرو دستگاه با REST، **دروازه‌ی Appium**، توکن API و دستور `ci run` که همیشه دستگاه را آزاد می‌کند
- 🧹 **پاک‌سازی بین کاربران:** هنگام آزاد کردن، برنامه‌ها متوقف و داده‌شان پاک (یا برنامه حذف) و مدیا پاک می‌شود؛ تا تمام نشود کسی نمی‌تواند دستگاه را بردارد
- 🎥 **ضبط سشن:** ویدیو و لاگ دستگاه، قابل پخش در رابط کاربری
- 🔐 **ورود واقعی:** OpenID Connect (با PKCE) و LDAP، با نگاشت گروه به ادمین
- 🪝 **وب‌هوک:** رویدادهای امضاشده با HMAC، همراه با تلاش مجدد و گزارش ارسال
- ✦ **دستیار:** «گوشی‌های سامسونگ آزاد با اندروید ۱۳ به بالا» تبدیل به یک کوئری می‌شود؛ با یک کلیک کوچک‌ترین مجموعه‌ی دستگاهی که بیشترین نسخه، برند و اندازه‌ی صفحه را پوشش می‌دهد پیشنهاد می‌شود
- 🧪 **شبیه‌ساز داخلی:** با `--fake 8` گوشی مجازی می‌گیرید و همه‌چیز (حتی UI) را بدون سخت‌افزار امتحان می‌کنید
- 🍎 **iOS (آزمایشی):** با libimobiledevice و WebDriverAgent

## شروع سریع (بدون سخت‌افزار)

<div dir="ltr">

```bash
git clone https://github.com/<your-user>/devicefarmz.git
cd devicefarmz
npm install
npm run build
npm run dev:demo        # هاب روی 7100، رابط روی 5173، با ۸ دستگاه شبیه‌سازی‌شده
```

</div>

آدرس **http://localhost:5173** را باز کنید و با ورود آزمایشی وارد شوید.

## گوشی‌های اندروید واقعی

<div dir="ltr">

```bash
npm run setup:tools     # adb و فایل jar استریم ویدیو را در ./tools دانلود می‌کند
npm run doctor          # Node، adb، دستگاه‌های وصل‌شده و jar ویدیو را بررسی می‌کند
npm run build
npm start               # http://localhost:7100
```

</div>

۱. روی هر گوشی **Developer options ← USB debugging** را روشن کنید و پیام RSA را تأیید کنید.
۲. گوشی را به ماشینی که هاب روی آن اجراست وصل کنید (هاب USB برق‌دار پیشنهاد می‌شود).
۳. چند ثانیه بعد در رابط کاربری ظاهر می‌شود.

اگر adb دارید فقط `ADB_PATH` را تنظیم کنید. بدون فایل jar ویدیو، هاب به استریم اسکرین‌شات برمی‌گردد (همه‌جا کار می‌کند ولی کندتر است). برای ذخیره‌ی ضبط‌ها به‌صورت mp4، `ffmpeg` نصب کنید.

## CI و Appium

در بخش *Settings* یک **توکن API** بسازید و دستور خود را روی دستگاه رزروشده اجرا کنید:

<div dir="ltr">

```bash
export DEVICEFARMZ_URL=https://farm.example.com
export DEVICEFARMZ_TOKEN=dfz_...

devicefarmz ci run --query "android>=13" --wait 120 --label "$BUILD_ID" -- ./gradlew connectedCheck
```

</div>

متغیر `DEVICE_UDID` برای دستور شما تنظیم می‌شود و دستگاه بعد از پایان — حتی اگر دستور شکست بخورد — آزاد و پاک‌سازی می‌شود. نمونه‌ی workflow در [`examples/github-actions.yml`](examples/github-actions.yml) است.

برای Appium، کلاینت را به‌جای سرور Appium به `/appium` روی هاب وصل کنید و در capabilityها می‌توانید `devicefarmz:query`، `devicefarmz:ttl` و `devicefarmz:waitSec` بدهید (جزئیات و نمونه‌کد در [README انگلیسی](README.md#-ci-and-appium)).

<div dir="ltr">

manufacturer:samsung   model:pixel        platform:android
battery>50             battery<20         available   busy   offline

## نکات امنیتی

- قبل از دسترسی دادن به دیگران، `DEVICEFARMZ_JWT_SECRET` را روی یک مقدار تصادفی بلند بگذارید.
- ورود آزمایشی فقط وقتی پیش‌فرض روشن است که OIDC/LDAP تنظیم نشده باشد. هابی که در دسترس عموم است نباید با آن اجرا شود.
- هاب را پشت HTTPS بگذارید (آپگرید WebSocket روی `/ws` باید مجاز باشد).
- توکن‌های API به‌صورت هش SHA-256 ذخیره می‌شوند و فقط یک‌بار نمایش داده می‌شوند. مدیریت وب‌هوک فقط برای ادمین است.
- دسترسی به شل یعنی کنترل کامل گوشی؛ در آزمایشگاه مشترک از حالت پاک‌سازی `clean` یا `uninstall` استفاده کنید.

## وضعیت و محدودیت‌ها

نسخه‌ی ۱٫۰٫۰ از نظر امکانات کامل است و کل جریان کار با شبیه‌ساز تست خودکار دارد. با این حال:

- استریم H.264 روی گوشی واقعی، مسیر iOS/WebDriverAgent، OIDC و LDAP طبق پروتکل‌های مستند پیاده‌سازی شده‌اند اما با ماک‌های سطح پروتکل (adb و استریم H.264 ساختگی، سرور WDA ساختگی، ارائه‌دهنده OIDC و دایرکتوری LDAP ساختگی) تست خودکار دارند و `npm test` همه را بدون سخت‌افزار اجرا می‌کند؛ این تست‌ها درستی پیاده‌سازی پروتکل را نشان می‌دهند، نه رفتار یک گوشی یا سرویس مشخص؛ مشکلاتی که روی سخت‌افزار یا سرویس واقعی دیدید گزارش کنید.
- ضبط دستگاه‌های شبیه‌سازی‌شده فقط لاگ دارد.
- دستگاه‌ها باید به همان ماشینی وصل باشند که هاب روی آن اجراست؛ `adb connect` راه دور هنوز پشتیبانی نمی‌شود.
